# EcoChill 水蓄冷/蓄热替换设计

## 1. 背景与目标

EcoChill 当前将储能建模为电池系统，界面和 Mock 数据使用 SOC、电池容量、PCS 充放电功率、健康度及循环次数等指标。项目现调整为水蓄冷/蓄热系统：在谷电或光伏富余时段由制冷机组或热泵制取冷水/热水并储存，在高电价或高负荷时段释放冷量/热量，减少主机峰时用电。

本次调整保留现有 Vue 大屏的页面结构、场景回放、AI 决策、设备详情和三维交互框架，替换储能业务模型、能源平衡、展示语义、Mock 数据、三维设备表达及项目文档。完成后，系统应能在制冷季和供热季分别演示水蓄冷、水蓄热的充能、待机和放能过程，并避免把冷/热功率当作电力供给直接计入电功率平衡。

## 2. 设计原则

1. **电与热分账。** 光伏、电网和设备用电使用电功率 kW；充冷、放冷、充热和放热使用热功率 kWth。两类功率不得直接相加。
2. **节费与节能分开。** 项目主要展示移峰、需量控制和光伏消纳收益，不默认宣称总用电量下降。
3. **储能状态互斥。** 同一等效储罐在一个时刻只能充能、放能或待机。
4. **容量与功率双约束。** 储罐剩余可用能量决定可持续时长，泵、管路和换热能力决定瞬时放能功率。
5. **保留现有交互。** 继续使用 `storage` 作为内部节点标识，减少无关的组件和路由改动；对外名称改为“水蓄能系统”或具体的“蓄冷/蓄热”。
6. **演示参数可解释。** 当前数据仍为 Mock，但所有关键参数应带明确单位、满足边界，并能用简单公式复核。

## 3. 范围

### 3.1 本次包含

- 将电池储能数据类型替换为水蓄冷/蓄热数据类型。
- 增加制冷季、供热季运行模式，并与现有天气、电价场景组合。
- 重建逐时充放能、储能率、主机用电和电网购电 Mock 数据。
- 调整 KPI、趋势图、能源结构、设备详情、告警、AI 策略和演示脚本。
- 将三维场景中的电池柜语义替换为分层储水罐及其水力连接。
- 更新 README 和项目说明文档中的设备、计算口径及落地建议。
- 增加关键计算与边界条件的自动化验证。

### 3.2 本次不包含

- 真实水泵、阀门、冷热源或楼宇自控系统接入。
- 水力管网瞬态仿真、泵扬程计算及 CFD 罐内分层模拟。
- 施工图、设备选型、结构荷载、消防、保温厚度和水处理设计。
- 依据特定城市电价形成正式投资回报报告。
- 同一储罐在同一时刻同时蓄冷和蓄热。

## 4. 方案选择

采用“物理逻辑一致的完整替换方案”：保留现有界面框架，重构储能数据模型与业务计算。

未采用仅替换文案的方案，因为原有 SOC、PCS、电池放电供电和电池循环次数会与水蓄能原理冲突。未采用工程级水力仿真方案，因为当前产品定位是竞赛答辩与数字孪生演示，工程级模型会显著增加输入数据和验证成本，却不会改善当前核心演示目标。

## 5. 领域模型

### 5.1 运行模式

新增独立于现有场景的季节运行模式：

- `cooling`：制冷季，展示充冷、蓄冷和放冷。
- `heating`：供热季，展示充热、蓄热和放热。

现有 `normal`、`heatwave`、`cloudy`、`peakPricing` 继续表示天气或电价场景。运行模式与场景组合生成仪表盘数据，例如“制冷季 + 高温热浪”或“供热季 + 峰值电价”。

### 5.2 储能指标

原 `StorageMetrics` 替换为热储能指标，至少包含：

| 字段 | 单位 | 含义 |
| --- | --- | --- |
| operationMode | cooling/heating | 当前季节运行模式 |
| state | charging/discharging/standby | 充能、放能或待机 |
| capacityKwhTh | kWhth | 设计可用冷/热量 |
| storedEnergyKwhTh | kWhth | 当前可用冷/热量 |
| storageLevelPct | % | 当前储能率 |
| chargePowerKwTh | kWth | 充冷或充热功率 |
| dischargePowerKwTh | kWth | 放冷或放热功率 |
| tankVolumeM3 | m³ | 有效水容积 |
| supplyTempC | ℃ | 当前供水温度 |
| returnTempC | ℃ | 当前回水温度 |
| roundTripEfficiencyPct | % | 计入静置和换热损失的等效效率 |
| availableHours | h | 按当前放能功率估算的可供时长 |

不再使用电池健康度、循环次数和 PCS 充放电功率。设备健康评分可由温度分层质量、传感器状态、泵组状态和可用容量派生，但不伪装为电池 SOH。

### 5.3 逐时数据

逐时数据同时保留电侧与热侧变量：

- 电侧：光伏功率、基础用电、主机用电、泵组用电、电网购电、电价。
- 热侧：建筑冷/热负荷、充能功率、放能功率、主机供冷/供热功率、储存能量。

电侧平衡为：

> 光伏实际利用 + 电网购电 = 基础用电 + 主机用电 + 泵组用电 + 其他边界内用电 + 上网功率

热侧平衡为：

> 主机直接供能 + 储罐放能 = 建筑冷/热负荷

充能时，主机制取的部分冷量/热量进入储罐；放能时，储罐减少主机需要直接承担的负荷。放能功率不作为电力来源。

### 5.4 储能递推

每一时段按下式更新储存能量：

> 下一时段储能量 = 当前储能量 + 充能功率 × 时长 × 充能效率 − 放能功率 × 时长 ÷ 放能效率 − 静置损失

更新结果限制在 0 到设计可用容量之间。达到上限后停止充能；达到下限或备用边界后停止放能。充能功率和放能功率必须互斥，并分别受设备额定功率限制。

### 5.5 容量解释

水显热储能的演示校核采用：

> 储能量（kWhth）≈ 1.163 × 有效水量（m³）× 有效供回水温差（℃）

Mock 数据中的容量、罐体容积和温差必须在允许误差内相互对应。制冷季与供热季可以使用不同的有效温差，因此同一罐体在两种模式下的可用储能量可以不同。

## 6. 调度策略

调度目标按优先级处理：

1. 满足舒适度、安全和最低备用要求。
2. 优先直接利用光伏满足当前设备用电。
3. 在光伏富余或谷价时段，根据负荷预测进行充冷或充热。
4. 在峰价、尖峰需量或高负荷时段优先放能，降低主机电功率。
5. 储能不足时由主机补足，电力不足时由电网补足。

默认采用部分蓄能策略：储罐与主机可在高峰时段共同承担负荷。只有在储能量和放能功率同时足够时，界面才显示主机停机或仅保留辅助运行。

光伏富余通常发生在白天，不与“夜间谷电”绑定。AI 决策文案应分别描述“谷电充能”和“光伏富余充能”。

## 7. 经济性与环境指标

单时段节费按避免的主机用电与新增充能、泵组用电计算：

> 净节费 = 峰时减少的主机用电 × 峰时电价 − 充能新增用电 × 充能时电价 − 新增泵组及辅助用电费用

累计收益还可包括最大需量降低，但需量收益必须单列，不能与电度电费重复计算。

项目应分别展示：

- 用电量变化；
- 电网购电量变化；
- 峰值购电功率变化；
- 电度电费变化；
- 最大需量费用变化；
- 光伏自用率变化；
- 舒适度与未满足负荷。

碳减排只根据明确的基线和分时电力排放因子估算。若没有可靠因子，界面应标识为演示估算，不将移峰收益自动等同于减碳。

## 8. 界面调整

### 8.1 顶部与总览

- 增加制冷季/供热季切换入口。
- 顶部核心 KPI 继续显示系统功率、经济收益、绿电占比和舒适度；“节能率”调整为可追溯的“峰值削减率”或“主机峰时减载率”。
- 当前模式、场景和数据时间保持可见。

### 8.2 水蓄能设备卡片

核心指标显示储能率、可用冷/热量、充放能功率、供回水温度及可供时长。状态文本根据运行模式显示“充冷中”“放冷中”“充热中”“放热中”或“保温待机”。

设备详情补充分层储水罐的容积、设计温差、等效效率和运行建议。趋势预览使用 kWth 或 kWhth，标题和坐标明确热功率/热量单位。

### 8.3 图表

- 电力趋势图：展示光伏、电网、总用电、主机用电和泵组用电。
- 热负荷趋势图：展示建筑冷/热负荷、主机直接供能和储罐放能。
- 储能趋势图：展示储能率、充能功率和放能功率。
- 能源结构图：电侧只显示光伏直供和电网供电；热侧另行显示主机直接供能与储罐供能比例。
- 收益图：保留峰谷电价，并将收益解释为移峰和主机减载收益。

### 8.4 AI 决策与告警

AI 决策应使用以下信息：电价、光伏预测、冷热负荷预测、当前储能率、供回水温差、最大充放能功率及舒适度约束。

告警至少覆盖：

- 储能接近上限或下限；
- 充放能同时出现；
- 供回水温差不足；
- 放能能力不足以覆盖目标削峰；
- 高峰前储能准备不足；
- 传感器或数据过期。

## 9. 三维场景

保留 `storage` 节点和原有聚焦交互，将视觉对象从电池柜改成保温分层储水罐。场景至少表达：

- 储水罐主体与冷热分层视觉提示；
- 冷热源机组、储罐和建筑末端之间的管路关系；
- 充能时从主机到储罐的流向；
- 放能时从储罐到建筑末端的流向；
- 制冷季使用冷色流光，供热季使用暖色流光；
- 待机时停止流动动效并保留储能率状态。

本次不要求新增外部 3D 资产。优先使用 Three.js 基础几何体重构水罐和管线，保证离线可用并避免资产许可问题。

## 10. 组件与文件边界

主要调整范围：

- `src/types/energy.ts`：运行模式、热储能、逐时电热数据类型。
- `src/mock/energyMock.ts`：季节参数、热储能递推、电热平衡、场景文案和告警。
- `src/store/dashboard.ts`：模式状态、设备详情指标和建议。
- `src/components/charts/`：电侧、热侧、储能和收益图表口径。
- `src/components/panels/`：水蓄能指标、模式切换及 AI 文案。
- `src/components/three/` 与 `src/three/`：储水罐和冷热流向。
- `README.md` 与项目说明文档：产品定位、设备组成、指标定义和落地边界。

热储能计算应集中在纯函数中，避免把容量递推和能量平衡散落在 Vue 组件内。组件只负责展示已计算的数据和发送模式切换操作。

## 11. 异常与降级处理

- 输入缺失或非法时使用安全默认值，并在运行元数据中标记为演示数据异常。
- 储能率统一限制在 0% 至 100%，温度与功率采用有限值校验。
- 模式切换时重建对应场景数据，避免沿用另一模式下不兼容的温度和储能容量。
- 当储能不足时，自动增加主机供能，不产生未解释的负荷缺口。
- 当光伏不足时，允许电网补电，不产生负购电或凭空消失的电量。
- 图表无数据时显示空状态，不用零值伪装为正常运行。

## 12. 验证标准

自动化验证至少覆盖：

1. 24 小时每个时段电侧功率平衡成立。
2. 24 小时每个时段热侧功率平衡成立。
3. 储能量始终位于容量边界内。
4. 任一时段充能与放能不同时为正。
5. 制冷季与供热季使用正确的状态文案、温度方向和单位。
6. 光伏为零、储能为空、储能已满、高负荷和高峰电价场景能够安全降级。
7. 峰时放能只通过减少主机用电影响电网购电，不直接计入电力供给。
8. 容量、罐体容积和设计温差满足显热储能公式的一致性校核。
9. TypeScript 类型检查和生产构建通过。

人工验收至少覆盖：

- 两种季节模式都能完成总览、设备聚焦、详情弹窗和演示回放。
- 三维场景中的设备、颜色和流向与当前模式一致。
- 所有 kW、kWth、kWh 和 kWhth 单位清晰且不混用。
- 界面不再出现 SOC、PCS、电池健康度、循环次数和电池柜等残留概念。

## 13. 迁移顺序

1. 建立热储能纯函数与数据类型，并用验证覆盖能量边界。
2. 重建 Mock 场景与逐时数据，先保证电热平衡。
3. 更新 Store、设备详情和 AI 决策。
4. 更新图表与面板，完成单位分离。
5. 更新三维储水罐和能量流。
6. 更新 README 与项目说明文档。
7. 执行类型检查、生产构建、自动化验证和人工页面检查。

该顺序优先解决业务正确性，再处理视觉表达，避免界面先完成但底层仍沿用电池逻辑。
