# EcoChill UI 与数字孪生重构设计

- 日期：2026-07-28
- 状态：已确认
- 设计基准：1920×1080，同时适配常规桌面与移动端
- 视觉方向：工业数字孪生控制中心 + 电影级全息科技

## 1. 背景

EcoChill 当前是一个基于 Vue 3、Vite、Pinia、ECharts 与 Three.js 的校园能源调度大屏。项目已具备光伏、空调、储能、AI 决策、场景切换和答辩演示等业务能力，但 UI 信息层级、视觉品质和 3D 场景完成度不足以形成高级的工业控制中心体验。

当前技术基线：

- 生产构建可以通过。
- 生产 JavaScript 为单个约 1.69 MB 的文件，gzip 后约 528 KB，并触发 Vite 大包警告。
- Three.js 场景主要由基础几何体组成，缺少统一的资产、材质、灯光和后期处理管线。
- 页面拥有底部图表组件，但未接入主页面。
- 主 Store 同时承担数据、计时器、场景交互和答辩播放等职责。
- 当前数据以 Mock 为主，本轮不建设真实数据接入能力。

## 2. 目标

### 2.1 体验目标

- 将首页重构为专业的中央能源调度指挥舱。
- 让 3D 校园数字孪生成为第一视觉中心。
- 增强电影级全息科技效果，同时保持指标、图表和告警清晰可读。
- 建立明确的供给侧、调度侧、分析侧信息结构。
- 支持答辩大屏、普通桌面浏览器和移动端。

### 2.2 工程目标

- 将 Three.js 单文件场景拆为职责明确的系统。
- 建立 GLB 模型与程序化效果结合的混合资产方案。
- 将 Mock 数据升级为可控、可复现的仿真时间轴。
- 拆分首屏代码，降低当前单包体积。
- 建立性能降级、资源失败降级和视觉回归验证机制。

## 3. 非目标

- 本轮不接入 WebSocket、IoT、真实后端或实时传感器。
- 本轮不实现真实 AI 调度算法。
- 本轮不建设多页面管理后台、账号系统或权限系统。
- 本轮不追求写实城市级 GIS，也不制作完整校园 BIM。
- 不使用高强度霓虹赛博风，不以持续闪烁或大面积辉光制造科技感。

## 4. 方案选择

采用“中央调度指挥舱”作为主结构，并吸收沉浸式数字孪生方案的局部表现力。

未选择的方案：

- 全屏沉浸式数字孪生：视觉冲击强，但图表可读性、操作效率和移动适配较弱。
- 高密度工业监控台：更接近生产后台，但比赛现场的第一眼吸引力不足。
- 全程序化 3D：性能和可控性好，但难以达到目标模型细节。
- 全 GLB 场景：视觉细节高，但数据联动、场景变化和性能治理成本较高。

最终采用混合方案：核心建筑和能源设备使用优化后的 GLB；能源流、全息标注、扫描波、数据柱和状态效果由 Three.js 程序化生成。

## 5. 页面架构

```text
┌ 品牌 / 全局状态 ─ 核心 KPI ─ 场景控制 / 答辩控制 ┐
├──────────┬──────────────────────┬──────────┤
│ 供给侧   │                      │ 调度侧   │
│ 光伏     │   3D 数字孪生主场景  │ AI 策略  │
│ 环境     │   能量流 / 设备状态   │ 空调负荷 │
│ 能源结构 │   场景内关键指标      │ 储能状态 │
├──────────┴──────────────────────┴──────────┤
│ 趋势工作台：功率 / 节能碳排 / 收益 / 决策记录 │
└────────────────────────────────────────────┘
```

### 5.1 顶部指挥栏

- 合并现有标题栏与答辩控制条。
- 左侧展示品牌、数据模式和系统状态。
- 中部展示少量全局 KPI，不重复两侧面板数据。
- 右侧放置场景切换、时间轴、答辩播放和全屏命令。

### 5.2 供给侧信息轨

- 展示光伏实时输出、天气环境和能源结构。
- 默认只展示当前最重要的数值和微型趋势。
- 详细趋势进入底部工作台，避免堆叠多个小图。

### 5.3 数字孪生主视口

- 采用无装饰卡片边框的主视口，让场景自然延伸到中部区域边缘。
- 场景内只放置绿电占比、网购电功率、当前对象等关键 HUD。
- 全息标签与设备位置绑定，自动避让并限制同时显示数量。

### 5.4 调度侧信息轨

- 按“AI 建议 → 空调负荷 → 储能执行 → 告警”组织。
- AI 面板突出建议动作、依据、预期收益和置信度，不展示大段说明文案。
- 告警使用固定语义色并支持定位到 3D 对象。

### 5.5 趋势工作台

- 将现有 `BottomPanel` 接入主页面并重构为标签式分析工作台。
- 标签包含功率趋势、节能碳排、收益分析和决策记录。
- 默认只挂载活动标签的图表，其他标签按需加载。

### 5.6 设备详情

- 由居中弹窗改为右侧详情抽屉。
- 抽屉打开时保留主场景可见，并自动调整镜头构图。
- 详情包含状态、核心指标、短时趋势、关联告警和建议动作。

## 6. 视觉系统

### 6.1 色彩

- 页面背景：近黑石墨灰。
- 表面层级：冷灰金属色，不使用整页深蓝单色调。
- 数据流与交互：青色。
- 正常运行：绿色。
- 关注与预警：琥珀色。
- 严重告警：红色。
- 正文：冷白与分级灰色。

颜色必须具有稳定业务语义。装饰元素不得占用告警色。

### 6.2 形状与层级

- 面板圆角统一为 4–6px。
- 使用细分隔线、表面明暗和留白建立层级。
- 不嵌套卡片，不为每个数值创建独立浮动卡片。
- 控制按钮优先使用 Lucide 图标；不熟悉的图标提供 tooltip。
- 模式切换使用分段控制器，二元状态使用开关或复选框。

### 6.3 字体与数字

- 中文使用系统无衬线字体栈，保证现场设备无需联网即可显示。
- 数字开启 `tabular-nums`，避免实时变化导致布局抖动。
- 只在全局 KPI 使用大号数字，面板标题保持紧凑。
- 字号不随视口宽度连续缩放，通过断点调整排版。

### 6.4 科幻特效

- 使用局部扫描线、技术刻度、视口角标和细微表面噪点。
- 能量流、选中对象和告警可使用选择性辉光。
- 持续动画必须表达状态变化，不添加无业务含义的闪烁。
- 支持 `prefers-reduced-motion`，降低扫描、粒子和镜头运动。

## 7. Three.js 数字孪生架构

### 7.1 场景分层

1. 工业底座层：地面、边界、道路和网格。
2. 校园建筑层：教学楼、图书馆和实验楼。
3. 能源设备层：光伏、冷站、储能和电网接口。
4. 能量网络层：管线、流动粒子、能量方向和强度。
5. 实时数据层：状态灯、数据柱、热力层和空间标签。
6. 后期特效层：选择性辉光、色调映射、轻量景深和边缘暗角。

每层必须能够独立启用、关闭或降级。

### 7.2 场景世界观

采用“未来化校园数字孪生”：保留真实可识别的校园建筑、光伏屋顶、冷站、储能柜和电网接口，通过全息底座、能源管网、扫描层和空间数据增强未来感。

### 7.3 资产策略

- 核心建筑和设备使用许可明确、经过压缩的 GLB 模型。
- 建筑、光伏、冷站和储能四类核心对象各至少包含一套随站点部署的 GLB 资产。
- 重复对象使用 `InstancedMesh`。
- 模型优先使用 PBR 材质和合理的纹理分辨率。
- 使用 Draco 或 Meshopt 压缩几何数据，使用 KTX2 压缩纹理。
- 第三方资产在仓库文档中记录来源、作者与许可证。
- GPT Image 只用于确有必要的材质贴图或环境背景，不用于伪装 3D 场景。

### 7.4 灯光与材质

- 使用环境光照、主方向光和少量设备局部光源。
- 使用接触阴影或轻量阴影增强落地感。
- 建筑主体保持低反射，能源设备与状态灯使用受控的金属度和自发光。
- 不允许所有材质同时高亮或泛蓝。

### 7.5 后期处理

- 使用 `EffectComposer` 组织渲染管线。
- 选择性 Bloom 只作用于能源流、选中设备、扫描波和告警。
- 桌面高档模式启用轻量景深；中低档与移动端关闭。
- 色调映射、曝光和暗角使用固定设计令牌统一控制。

### 7.6 动态效果

- 全息扫描波沿目标设备或园区区域扩散。
- 地面网格根据当前场景产生局部数据响应。
- 能量管线的颜色、速度、宽度和粒子密度映射到功率与方向。
- 设备状态灯映射到正常、关注、告警和离线状态。
- 热浪、云层、低照度和储能放电效果随场景模式变化。

### 7.7 镜头与交互

- 提供总览、光伏、冷站、储能和告警定位预设。
- 镜头过渡使用统一缓动，不直接跳变。
- 用户手动旋转或缩放后暂停自动巡航，空闲后再恢复。
- 点击 3D 对象同步面板、告警和详情抽屉。
- 指针移动射线检测需要节流，移动端使用点击选择。

## 8. 组件边界

页面组件：

- `CommandHeader`：品牌、系统状态、全局 KPI 和命令。
- `SupplyRail`：供给侧数据。
- `TwinViewport`：3D 容器与 HUD。
- `DispatchRail`：AI、负荷、储能和告警。
- `AnalyticsDock`：标签式趋势工作台。
- `DeviceInspectorDrawer`：设备详情。

3D 模块：

- `TwinSceneManager`：生命周期、渲染和帧循环。
- `AssetLoader`：GLB、纹理、压缩器和加载进度。
- `EnvironmentSystem`：灯光、天空、地面和场景模式。
- `EnergyFlowSystem`：能量路径与粒子。
- `DeviceInteractionSystem`：选中、悬停和空间标签。
- `PostProcessingPipeline`：后期效果与质量等级。

状态模块：

- `simulationStore`：Mock 仿真时间轴和派生数据。
- `twinStore`：选中对象、镜头与 3D 状态。
- `presentationStore`：答辩章节、播放和暂停。

## 9. Mock 仿真数据流

```text
场景脚本 + 时间轴
        ↓
可复现的 Mock 仿真快照
        ↓
simulationStore
        ↓
图表 / KPI / 告警 / 设备状态 / 能量流
```

- 四种场景使用固定、可复现的数据曲线。
- 时间轴支持播放、暂停、拖动、跳转和重置。
- 自动答辩模式按照章节切换场景、时间、镜头和选中设备。
- 图表、告警、3D 灯光和能源流必须消费同一时刻的快照。
- 保留现有服务接口作为未来扩展边界，但本轮不增加真实 API 逻辑。

## 10. 响应式策略

### 10.1 1920×1080

- 三列主布局完整展示。
- 趋势工作台固定在底部，可折叠。
- 3D 使用高质量渲染档位。

### 10.2 1440×900 与常规桌面

- 3D 保持首要区域。
- 两侧信息轨缩窄，次要内容折叠。
- 趋势工作台以覆盖式底部面板展开。

### 10.3 移动端

- 内容顺序为全局 KPI、3D、告警与 AI、详细数据。
- 两侧信息轨变为抽屉或折叠区。
- 3D 使用稳定纵横比，不被动态内容挤压。
- 关闭景深、部分粒子、透明叠层和高分辨率阴影。

## 11. 性能设计

- 桌面目标稳定 50 FPS 以上，移动端目标 30 FPS 以上。
- 自适应像素比上限按设备档位设定，不固定使用高 DPR。
- 页面隐藏时暂停 Three.js 帧循环、时间轴和自动轮播。
- 使用 LOD、实例化、共享几何体和共享材质减少绘制开销。
- UI、Three.js 和 ECharts 拆分为独立异步模块。
- UI 入口 JavaScript 目标不超过 180 KB gzip，全部 JavaScript 目标不超过 480 KB gzip；3D 模型与纹理单独计入资产预算。
- ECharts 使用按需注册，不再导入完整包。
- 仅挂载当前可见的趋势图表。
- 监听容器尺寸，不依赖全局窗口 resize 作为唯一尺寸来源。
- Three.js 销毁时释放几何体、材质、纹理、后期处理和渲染器资源。

## 12. 加载、错误与降级

- 加载顺序为基础 UI、核心场景、次要模型、增强特效。
- 显示真实资产加载进度，不使用无限循环假进度。
- 单个 GLB 或纹理失败时使用对应低模或基础材质替代。
- 后期处理创建失败时退回基础 WebGL 渲染。
- WebGL 不可用时显示二维能源拓扑、核心 KPI 和场景控制。
- 错误信息写入非阻塞状态区，不使用阻断演示的浏览器弹窗。
- 所有演示必需资源随静态站点部署，现场断网仍可运行。

## 13. 可访问性与控制

- 所有图标按钮提供可访问名称和 tooltip。
- 键盘可操作场景模式、时间轴、标签页、抽屉和答辩播放。
- 焦点样式在深色背景上清晰可见。
- 告警不只依赖颜色，同时使用图标、文本与层级。
- 支持触摸点击、抽屉手势的基本交互，不依赖 hover 才能查看关键信息。

## 14. 测试与视觉验证

### 14.1 单元测试

- 仿真时间轴的播放、暂停、拖动和循环。
- 四种场景的派生 KPI 与告警。
- 答辩章节切换和播放状态。
- 场景选择与面板选择的双向同步。
- 资源加载失败后的降级选择。

### 14.2 浏览器测试

- 场景模式、时间轴和答辩控制可操作。
- 点击 3D 设备能打开正确详情。
- 趋势标签按需加载且图表非空。
- 抽屉、底部工作台和移动端折叠逻辑正确。

### 14.3 视觉验证

- 使用 Playwright 截图验证 1920×1080、1440×900 和 390×844。
- 检查文字、控制器、HUD、图表和抽屉无重叠。
- 使用画布像素检查确认 Three.js 场景非空且不是纯背景色。
- 验证 GLB、纹理、辉光、能量流和场景模式效果正确显示。
- 验证 `prefers-reduced-motion` 下的降级效果。

## 15. 验收标准

- 页面第一视口呈现明确的品牌、能源调度主题和 3D 校园孪生。
- 视觉风格符合工业控制中心与电影级全息科技方向。
- 核心业务对象仍为教学楼、图书馆、实验楼、光伏、冷站、储能和电网。
- 建筑、光伏、冷站和储能 GLB 均随站点离线可用，并附带可核验的许可证记录。
- 供给侧、3D 主场景、调度侧和趋势分析之间的信息层级清晰。
- 四种 Mock 场景可通过统一时间轴稳定复现。
- 3D 能源流、设备状态、告警和图表在同一时间点保持一致。
- UI、Three.js 和 ECharts 形成独立异步包，满足 180 KB gzip 的入口预算和 480 KB gzip 的 JavaScript 总预算。
- 目标视口无内容溢出、遮挡和不可操作控件。
- 桌面和移动端达到对应帧率目标，并能按能力自动降级。
- 资源加载失败、WebGL 不可用和现场断网时均有可用降级界面。
