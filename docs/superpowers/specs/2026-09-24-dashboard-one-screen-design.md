# 大屏一屏展示设计

- 日期：2026-09-24
- 状态：方案已口头确认，待书面规格复核
- 基准视口：1920 × 1080 CSS 像素，浏览器缩放 100%
- 实施分支：`codex/campus-3d-upgrade`，与已完成但尚未合并的园区 3D 升级一起验收

## 目标与边界

当前页面由顶部信息区、三列主场景和底部分析图表自然撑高。`dashboard-shell` 只有 `min-height: 100vh`，3D 场景有最低高度，底部图表还占约 210px，因此在 1080p 下需要页面滚动。用户确认采用“核心信息一屏、详细分析浮窗”的方案，而不是把全部图表和文字强行缩小。

在基准视口下，首页不出现页面级水平或垂直滚动条。首屏同时可见：系统标题与四项核心 KPI、季节/场景切换、中央 3D 场景、左侧光伏和环境摘要、右侧空调负荷/水蓄能/AI 策略摘要，以及底部分析入口。任何现有详细指标、趋势图或决策记录不得删除；它们经现有设备详情或分析浮窗访问。正常桌面、平板和手机继续保留可滚动响应式布局，不套用强制一屏规则。

## 布局方案

1. 当 CSS 视口至少为 1800 × 1000 时启用一屏模式，使用固定视口高度的三段布局：紧凑顶部、可伸缩三列主体、薄底部分析入口。根容器使用 `100dvh`，主行和子网格允许 `min-height: 0`；仅在此模式关闭页面级滚动，不依赖浏览器缩放或 CSS `zoom`。
2. 中央 3D 场景是最大视觉区域，保持三列结构与原有相机、点击、悬停、缩放和告警行为。顶部压缩不删核心 KPI；将长摘要及重复状态收敛为更短的行内信息。
3. 两侧卡片在一屏模式展示关键数值和一句状态。高密度趋势图、天气细项、设备长说明、AI 规则全文通过原有详情/分析浮窗打开。摘要入口应明确可点击，并保留语义标签，不把不可见内容仅靠 hover 暴露。
4. 底部分析区在一屏模式变为单行入口栏，沿用六类分析浮窗。原四张完整图表在普通宽屏模式仍保持现状；一屏模式只改变首页呈现，不改变图表内容、数据或单位。
5. 若视口宽度、高度或浏览器缩放后的 CSS 可用空间不足，则退出一屏模式，恢复自然滚动。避免把 1366 × 768 等小桌面屏压成难读的微缩布局。

## 实现约束

- 不修改能源模拟、调度算法、实时数据接口或 3D 模型几何；仅调整页面排布及必要的摘要/浮窗入口。
- 不新增运行时依赖，不新增独立页面，不把详情内容永久隐藏。
- 保持键盘可访问性、按钮可见焦点、弹窗关闭与滚动行为。
- 一屏模式使用 CSS 媒体条件和组件内的呈现变体，避免将固定像素坐标写死到所有分辨率。
- 样式必须允许 Three.js 容器随主体高度正确 resize，不能拉伸画布或出现空白。

## 验收标准

1. 在 1920 × 1080、100% 缩放下，`document.documentElement.scrollHeight <= window.innerHeight + 1`，`scrollWidth <= innerWidth + 1`；顶部、左右摘要、中央 3D 和底部分析入口均落在视口内，无重叠、截字或空白带。
2. 中央 3D 仍清楚可见，切换总览/光伏/空调/蓄能视角及点击主要实体正常；冷热模式和场景切换不会令布局溢出。
3. 底部六类分析入口可打开并关闭对应浮窗；原趋势图与单位完整保留。设备详情、AI 决策说明也可从摘要进入。
4. 在 1440 × 900 和手机宽度下保持原响应式滚动布局，内容可达、无水平溢出。
5. 项目测试、类型检查、生产构建通过；浏览器检查控制台无新增错误。构建已有的大包体积提示不属于本轮布局缺陷。

## 风险与应对

- 侧栏内容高度不可控：一屏模式使用明确的摘要呈现，详情放浮窗；不要单纯 `overflow: hidden` 截掉不可达信息。
- 数据文案长度变化：关键数值优先、次要文案可省略，入口保留完整 `aria-label` 或标题。
- 仅以媒体查询判断缩放可能在 100% 以外触发不同布局：以浏览器实际 CSS 视口为准，验收明确固定在 100%。
