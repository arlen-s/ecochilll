# 园区 3D 主体升级设计

- 日期：2026-09-23
- 状态：已确认视觉方向与改造范围，待规格复核
- 视觉方向：方案 A，精细园区数字孪生

## 背景与目标

当前 Three.js 场景中的建筑、光伏、冷热源机房与电网接口主要由简单几何体和大面积自发光材质组成，远景可辨认位置，但近景缺少真实结构和尺度感。蓄能水罐已有冷热分层可视化，但设备细节与全场景的材质语言仍不统一。用户确认本轮升级所有主要实体，而非只增加建筑楼层。

目标是在现有相机与交互框架内，让建筑、能源设备和流线具有可辨认的真实形态，同时维持数字孪生大屏的清晰度与响应速度。不追求照片级写实、完整 BIM 或新增外部模型资产。

## 范围

1. **教学楼、图书馆、实验楼**：保留原位置、占地和屋顶高度；使用深色实体结构、玻璃窗格、楼层板、入口雨棚、屋顶女儿墙与少量设备。教学楼突出水平楼层；图书馆突出玻璃中庭与竖向格栅；实验楼突出技术机房与排风设备。三栋楼在同一材质体系下具有不同轮廓。
2. **屋顶光伏阵列**：保留现有 24 块板及两处屋顶分布；补充边框、电池片分格、倾斜支架与合理的反射，并微调单板间距与坐标，使面板真正落在屋顶承载范围内，不再悬浮或整面发绿。
3. **冷热源机房**：将当前发光底座、圆柱风扇和方形管道组合升级为可识别的设备底座、箱体、风机格栅、风管与管口，保留其占位和点击热区。
4. **分层蓄能水罐**：保留冷热/蓄热分层高度、颜色、界面与充放能脉冲逻辑；细化罐体支座、检修结构、泵、阀门及进出水管。任何新增不透明部分不得遮蔽分层读数。
5. **园区电网接口**：将细杆造型升级为明确的变配电柜、支架/立柱、绝缘子与连接导线；保持设备位置与告警语义。
6. **能量流线**：保留现有四条业务路径与场景/蓄能状态联动；用更细的实体管线、方向性流动脉冲和克制的发光替代粗重泛光，确保区分电力流与冷热水流。

不改动天空、云、背景平台、业务数据、调度算法或 UI 面板结构；仅在必要时微调物体附近底座，帮助新模型落地。若升级后遮挡焦点视角，可局部调整相机预设，但不改变交互模式。

## 实现边界

- 使用项目现有 Three.js 与 Vue 体系，不新增运行时依赖或外部 GLB。优先使用程序化几何、共享材质与 `InstancedMesh` 表达重复窗格、电池片、格栅，控制绘制开销。
- 将建筑与设备建模从过长的 `createEnergyScene.ts` 拆成独立工厂模块。每个工厂返回一个 `THREE.Group`，沿用 `id`、`label` 和 `interactive` 元数据；蓄能罐继续暴露现有动画需要的部件与材质引用。
- 建筑占地、屋顶高度与光伏阵列的两处分布保持一致；允许校正单块光伏板坐标，不得让新装饰物与光伏板、能量流线、相邻设备产生明显穿插。
- 灯光与材质采用深石墨、冷灰金属、蓝灰玻璃为主体；青色仅用于可操作状态与能量流，琥珀色保留给电网/警示语义，避免整面自发光。
- 点击、悬停、高亮、告警、场景切换、冷热模式、蓄能分层与资源释放维持现有行为。新增的可见网格归属原交互组，不另设业务节点。

## 验收标准

- 总览一眼可区分三栋建筑、光伏、冷热源、水罐与电网接口；近景可看到建筑窗格/入口和设备的功能性结构，而不再是单纯发光盒体。
- 24 块光伏板稳定贴合两处屋顶；水罐在蓄冷、放冷、蓄热、放热时仍正确显示分层与流向。
- 各主要实体在桌面与窄屏视角可见且可点击；无严重遮挡、穿模、闪烁、控制台错误或明显掉帧。
- 单元测试覆盖模型结构、关键尺寸/位置、交互元数据和状态联动；项目现有测试、类型检查与生产构建通过。浏览器逐一检查总览、光伏、空调、水罐视角，并检查电网接口和能量流。

## 风险与控制

- 重复窗格、格栅和面板会增加绘制调用：使用实例化网格、共享几何与材质，并避免逐帧创建对象。
- 透明玻璃与水罐壳体可能出现排序问题：建筑玻璃优先用不透明或低透明材质，水罐继续使用明确的 `renderOrder` 和 `depthWrite` 策略。
- 新模型可能改变射线命中优先级：沿用现有交互组及必要的透明命中体，在浏览器验证悬停与点击。
